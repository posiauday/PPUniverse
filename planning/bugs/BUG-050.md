Follows `planning/github/04-bug-template.md`. Found in the full-site code review the product owner asked for on 2026-10-10.

## Summary
Consent, deletion requests (and withdrawing one), free product claims and session sign-out skipped the same-origin check every other write route makes; consent also read any body as JSON, including a text/plain form post. Only the SameSite=Lax session cookie stopped another site from posting them.

## Cause
These routes predate the shared request guards (MVP-036) and were never moved onto them.

## Fix
All five answer 403 to a request without this site's Origin, before reading the session.

## Steps to reproduce
From another site, post a text/plain form to /api/account/consent while signed in.

## Expected behavior
Refused.

## Actual behavior
Refused only because the browser withheld the cookie.

## Security or privacy impact
Defence in depth: no known exploit while the cookie stays SameSite=Lax.

## Tests
account-origin.test.ts (no Origin and another site refused, this site passes); route tests updated to send the site's Origin.
