Follows `planning/github/04-bug-template.md`. Found while implementing MVP-023.

## Summary
`/signin` and `/account/sessions` render with browser-default styling: no design-system spacing, typography, button or form styling, unlike the home, catalog, search and product pages. The pages work and were measured only for the WCAG A/AA failures Q37 lists; they were deliberately **not** restyled or redesigned in MVP-023.

## Severity
- [x] P3 — minor content or admin issue (accessibility rubric Q35: **P4**, advisory only; not a WCAG A/AA failure)

## Affected requirement / feature
- NFR-001 (advisory). Delivered by MVP-002. `docs/05-ux-design-system.md` describes the intended look.

## Steps to reproduce
Open `/signin` or sign in and open `/account/sessions`.

## Expected behavior
The pages use the design system like the other pages.

## Actual behavior
Unstyled controls and spacing. Contrast and focus visibility of the controls were checked and pass (see `docs/14-accessibility-testing.md`), but the default styling means, for example, that touch-target size (WCAG 2.5.8) and text-spacing behavior are not something the design system has been applied to or reviewed for.

## Security or privacy impact
- [x] None.

## Accessibility impact
- [x] Advisory only; possible effect on target size and visual consistency. Apply `type:accessibility`.

## Suggested fix
Style both pages with the design-system components in a story that owns the sign-in and account experience; add the pages' states to the existing accessibility matrix (they are already in it) so the redesign is gated.
