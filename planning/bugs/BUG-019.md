Follows `planning/github/04-bug-template.md`.

## Summary
`apps/web/lib/email.ts` chose `ConsoleEmailAdapter` whenever `RESEND_API_KEY` was unset, in every environment including production ("production never fails to start"). That adapter logs the recipient and the full message body. For a sign-in email the body contains the magic link with its token, which is a working credential until it expires. A production deployment missing the key, or one where it was briefly removed, would write every visitor's email address and sign-in link to the hosting provider's function logs. Anyone with log access could then sign in as that visitor.

Found while inventorying personal-data handling for the privacy notice (open question 64).

## Severity
- [x] P1 — security. Credential disclosure into logs, triggered by a plausible misconfiguration.
- **Exposure: none.** No production deployment exists yet (MVP-030 slice 2 has not run).

## Steps to reproduce
1. Build and run the web app with `NODE_ENV=production` and no `RESEND_API_KEY`.
2. Request a sign-in link at `/signin`.
3. The server log shows `[email:dev] to=<address>` and `[email:dev] body=Sign in by opening this link ...: <url with token>`.

## Expected / actual
- **Expected:** production never logs a sign-in link. Without a provider, the send fails and the visitor is told the email couldn't be sent.
- **Actual:** production logged the address and the link, and told the visitor the email was sent.

## Why it was not caught earlier
The fallback was designed for local development and the accessibility gate. The gate runs a production build with no provider and relies on the console transport for its sign-in states, so "production uses the console transport" looked intended. No test checked what production does without a key.

## Resolution (2026-10-02)
- **New adapter:** `UnconfiguredEmailAdapter` (`packages/adapters/email/src/email-adapter.ts`) rejects every send and logs nothing about the message.
- **Selection:** `selectEmailAdapter` chooses the transport:
  - the provider when a key exists;
  - the console transport outside production, or when a harness sets `EMAIL_TRANSPORT=log`;
  - otherwise, fail closed.
- **Callers:** `apps/web/lib/email.ts` uses it. The accessibility gate's throwaway server sets `EMAIL_TRANSPORT=log` (`packages/e2e/playwright.config.ts`).
- **Visitor experience:** a failed send is recorded as `FAILED` and re-thrown, so next-auth shows its existing "couldn't send" error. next-auth logs only the error message and provider id, never the link.
- **Tests:** `email-adapter.test.ts` covers every branch of the selection, and checks that the unconfigured adapter rejects without logging anything.
