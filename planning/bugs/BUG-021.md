## Summary
`apps/web/netlify.toml` (MVP-030 slice 1) set `publish = ".next"`, with a comment saying the path was relative to the package directory (`apps/web`). Netlify resolves every path in `netlify.toml` from the base directory, the repository root, even when the file sits in a package directory (docs.netlify.com, "Monorepos").

So every git-triggered build resolved the publish directory to `/opt/build/repo/.next`:
- the build itself succeeded (all 26 Turborepo tasks);
- `@netlify/plugin-nextjs` then failed in `onBuild` with "Your publish directory was not found at: /opt/build/repo/.next".

## Severity
- [x] P1. Every production and preview deploy since `apps/web/netlify.toml` reached `main` fails, so the Daylight redesign release (#56) could not go live.
- **Exposure: none.** A failed deploy leaves the previous deploy published (`main@9d925d5`).

## Steps to reproduce
Merge anything to `main`, or open a PR, with base directory unset and package directory `apps/web`. The deploy log shows `publish: /opt/build/repo/.next` and the plugin error above.

## Expected / actual
- **Expected:** the plugin finds the Next.js output at `apps/web/.next` and publishes it.
- **Actual:** it looks in the repository root and fails.

## Why it was not caught earlier
- The only successful production deploy (`main@9d925d5`, 2026-10-01) was built from a commit without `netlify.toml`, using the UI's own settings.
- CI builds with `pnpm build` and never runs Netlify's plugin.
- The path rule was written from an assumption, not checked against Netlify's documentation.

## Resolution (2026-10-02)
`publish = "apps/web/.next"`, with a comment citing the base-directory rule. Verified by the fix PR's own Netlify Deploy Preview.
