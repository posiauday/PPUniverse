## Summary
GitHub advisory GHSA-vcvr-r3jv-pc5j (published 2026-09-30, severity critical) reports remote code execution in the Node.js `ImageResponse` implementation from `next/og`. It affects Next.js >=16.2.0 <16.3.6. The web app was on 16.3.5 (range `^16.3.5`), and it uses `next/og` to render share images (`apps/web/lib/seo/share-image.tsx`, MVP-026). CI's dependency audit (`pnpm audit --audit-level=high`) failed on PR #45 as a result, and it would fail on every branch until fixed.

## Severity
- [x] P0 — security. It's classified by type: a critical advisory in a runtime dependency on a code path we use.
- **Exposure: none.** The hosting decision is still open (`docs/open-questions.md` item 5), so no production deployment exists and nothing was exposed. No on-call paging applies.

## Is our code affected?
The advisory says affected applications pass attacker-controlled values into SVG content, attributes or styles. Applications using the Edge implementation, or not passing attacker-controlled values into SVG, are not affected.
- **Our code passes no explicit SVG.** `renderShareImage` builds a `div` tree with fixed styles. Its only variable inputs are an eyebrow string and a title, placed as text children.
- **The inputs don't come from the request.** Titles come from **published** database rows looked up by slug, never from the query string, and pass through `normalizeDisplayText` and a length cap.
- **Some inputs are still third-party text.** Product titles are written by creators, and Satori renders the whole tree to SVG internally.
- **Assessment.** On the advisory's own description we're very likely not exploitable, but that's our assessment, not a certainty. The upgrade is required either way.

## Steps to reproduce
Run `pnpm audit --audit-level=high` on `develop` at 2026-09-30 (before this fix). It reports 1 critical: `next` >=16.2.0 <16.3.6, paths `apps__web>next` and `apps__web>next-auth>next`.

## Expected / actual
- **Expected:** the dependency audit is clean.
- **Actual:** 1 critical vulnerability, and the "Format, lint, typecheck, test, build" job fails.

## Why it was not caught earlier
It wasn't a missed defect. The advisory was published on 2026-09-30, after 16.3.5 was adopted. The CI audit caught it on the first run after publication, as designed.

## Resolution (2026-09-30)
- **What changed.** `next` was upgraded to `^16.3.7` in `apps/web`, and `@next/eslint-plugin-next` to `^16.3.7` at the root to keep them matched.
- **Why 16.3.7, not 16.3.8.** 16.3.8 is the newest release, but it was published less than a day before the fix. Installing it made pnpm add `minimumReleaseAgeExclude` entries to `pnpm-workspace.yaml`, which bypass pnpm's minimum-release-age supply-chain safeguard. 16.3.7 is patched (>=16.3.6), about a day and a half old, and needs no exception, so no safeguard is weakened.
- **ADR impact.** This is a patch-level upgrade within the approved Next.js major, so no ADR change is needed (ADR-004 names Next.js without pinning a patch version).
- **Verified locally:**
  - `pnpm audit --audit-level=high` reports no known vulnerabilities;
  - lint and typecheck are clean;
  - every workspace test passes against a migrated local Postgres, including 465 web tests with the share-image tests (`lib/seo/share-image.test.ts`, `app/og/og-routes.test.ts`);
  - `pnpm build` succeeds on Next.js 16.3.7.
- **Still to do:** `main` still carries 16.3.5 until this fix is released there. Nothing is deployed, so the risk is only that a future deployment from `main` would use the vulnerable version.
