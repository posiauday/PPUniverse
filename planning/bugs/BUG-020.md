Follows `planning/github/04-bug-template.md`.

## Summary
`POST /api/files/uploads` and `POST /api/files/uploads/complete` checked only for a session. Any signed-in member could therefore mint a signed upload URL into the quarantine bucket and register the upload for scanning. This contradicts the first-party-only publishing model (`docs/final-decisions.md`, "First-party-only publishing model"): visitors never upload, and only the admin attaches files to releases.

Found while inventorying personal-data handling for the privacy notice (open question 64).

## Severity
- [x] P2 — security (authorization). Members could store arbitrary files, up to the upload policy's type and size limits, in project storage and trigger scanning work.
- **Exposure: none.** No production deployment exists, and object storage isn't configured for launch (`docs/15-deployment.md`), so the route can't mint a working URL there yet.

## Steps to reproduce
1. Sign in as a member (role `MEMBER`).
2. Send `POST /api/files/uploads` with `{"filename":"a.zip","declaredMimeType":"application/zip","sizeBytes":1024}`.
3. The response contains a `storageKey` and `uploadUrl`.

## Expected / actual
- **Expected:** only an admin gets an upload URL. Everyone else gets the same 404 the `/api/admin/*` routes give, so the route isn't revealed.
- **Actual:** any signed-in user got an upload URL.

## Why it was not caught earlier
The upload routes came from MVP-006, written when invited third-party creators were expected to upload. The first-party-only decision (2026-09-24) moved authoring under ADMIN in `/api/admin/*`, but these two routes sit outside that path and kept their session-only check.

## Resolution (2026-10-02)
- **Shared helper:** `apps/web/lib/require-admin.ts` provides `requireAdmin`, which re-queries the role from the database and never trusts the session, plus `notFoundForNonAdmin`.
- **Routes:** both upload routes now use them.
- **Unchanged:** `GET /api/files/[id]` still returns only the caller's own uploads.
- **Tests:** `app/api/files/uploads/route.test.ts`:
  - signed out → 404;
  - member → 404;
  - a session claiming ADMIN while the database says MEMBER → 404;
  - admin → a URL under the admin's id.
- **Not changed:** the existing `/api/admin/*` routes keep their inline copies of the same check. Moving them onto the helper is a separate cleanup.
