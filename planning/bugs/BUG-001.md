## Summary
Pages delivered by MVP-003/004/005 set `alternates.canonical` to a bare relative path, and no `metadataBase` is configured, so the emitted `<link rel="canonical">` and `og:url` carry no origin. The sign-in and account pages have no robots metadata, so they are indexable by default. Both fall within FR-017, which MVP-021 owns; they are recorded because they are defects in already-delivered pages.

## Severity
- [ ] P0 — security, payment, or data exposure
- [ ] P1 — checkout or download outage
- [ ] P2 — degraded search, notifications, or creator workflow
- [x] P3 — minor content or admin issue

No production deployment exists, so nothing has been exposed or mis-indexed.

## Affected requirement / feature
- Requirement ID: FR-017 (canonical URL, metadata, social preview)
- Delivered stories: MVP-003 (category page), MVP-004 (category canonical policy), MVP-005 (product page)

## Environment
- Environment: local production build (`next build` then `next start`, Next.js 16.3.5)
- User role: guest

## Steps to reproduce
1. The product page (`apps/web/app/products/[slug]/page.tsx`) and category page (`apps/web/app/categories/[slug]/page.tsx`) return `alternates: { canonical: "/products/<slug>" }` / `"/categories/<slug>"`. `apps/web/app/layout.tsx` sets no `metadataBase`.
2. Those pages need a database, which is unavailable locally, so the behavior was reproduced with a **temporary probe route** that used the same metadata shape (`alternates.canonical` and `openGraph.url` as relative paths, plus an `openGraph.images` entry), built and served in production mode. The probe was deleted.
3. Request the route and read the head tags.
4. Separately, inspect `apps/web/app/signin/page.tsx` and `apps/web/app/account/sessions/page.tsx`: neither exports metadata or robots directives, and `layout.tsx` sets none.

## Expected behavior
Absolute canonical and `og:url` URLs built from a configured site origin; sign-in and account pages carry `noindex`.

## Actual behavior
Probe output from the production server:
```
<link rel="canonical" href="/products/probe-item"/>
<meta property="og:url" content="/products/probe-item"/>
<meta property="og:image" content="http://localhost:3055/x.png"/>
```
- Canonical and `og:url` are relative. Search-engine guidance recommends absolute canonical URLs, and Open Graph requires an absolute `og:url`.
- Any relative social-image URL resolves against `http://localhost:<port>` when no `metadataBase` is set — wrong in production once images exist.
- Only `/search` sets `robots` (`noindex, follow`). Sign-in and account pages have no directive.

## Evidence
- Probe results above (production build, 2026-09-21). The source-level facts (no `metadataBase`, no robots on sign-in/account, relative canonicals) are from `grep` of `apps/web/app`.
- Caveat: the relative-canonical behavior was reproduced on a probe with the same metadata shape, not on the real product page, because no database is available locally.

## Security or privacy impact
- [ ] Unauthorized data access, authorization bypass, payment manipulation, or malware delivery. None identified. Indexable sign-in/account pages are an SEO/hygiene issue, not a data exposure: `/account/sessions` server-redirects unauthenticated visitors to `/signin` (verified in source), and `/signin` renders only a form.

## Accessibility impact
- [ ] None.

## Suggested fix
Fixed by MVP-021 as part of FR-017: `NEXT_PUBLIC_SITE_URL`-based absolute canonical/OG URLs, a default `noindex` posture with explicit opt-in for indexable pages, and robots/sitemap routes. Close this bug when MVP-021 is Done.
