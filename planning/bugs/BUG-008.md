Follows `planning/github/04-bug-template.md`. Found while measuring the accessibility baseline for MVP-023.

## Summary
No custom `not-found.tsx` (or `error.tsx`) exists, so an unknown URL renders the framework's default 404 page, which has no `<main>` landmark and inherits the site-name-only title. Known-missing products and categories use the same default page.

## Severity
- [x] P3 — minor content or admin issue

## Affected requirement / feature
- NFR-001. axe `landmark-one-main` and `region` (best-practice); WCAG 2.4.2 Page Titled (A) for the title; `docs/05` "required states" lists a system-error state that is not implemented.
- Delivered by MVP-003 (routing) and the framework default.

## Environment
Local dev server, axe-core 4.10.2, 4 widths, 2026-09-21. Guest.

## Steps to reproduce
Open any unknown URL, for example `/no-such-page-xyz`.

## Expected behavior
A 404 page with a `<main>` landmark, a heading, a descriptive title ("Page not found"), and a way back.

## Actual behavior
axe: `landmark-one-main` (moderate) ×1 and `region` (moderate) ×2 at every width; `document.title` is "Power Platform Universe". The page keeps its `noindex` behavior (verified in MVP-021).

## Evidence
44 axe scans; the finding is identical at all four widths.

## Security or privacy impact
- [ ] None.

## Accessibility impact
- [x] Affects landmark navigation and page identification. Apply `type:accessibility`.

## Suggested fix
Add `apps/web/app/not-found.tsx` rendering a `<main>` with an `h1`, descriptive metadata and a link home, styled with the design system. Cover with the MVP-023 not-found spec.

## Resolution
Fixed by MVP-023 F5 (commit db2f7cf: new `not-found.tsx` with a main landmark, an h1 and a link home) and F10 (commit 82f9113: descriptive title). Regression tests: `bug-008-not-found-landmark.spec.ts` and `bug-008-not-found-title.spec.ts`, shown failing before the fixes.
