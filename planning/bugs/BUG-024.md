# BUG-024: The admin product editor overflowed a 320px screen when a file scan id was wide

## Summary
On `/admin/products/[id]/edit`, each attached file is listed by its file scan id: a 25-character id with no break points, inside an indented list. With some ids the line was a few pixels wider than a 320px screen, so the page scrolled sideways. The ids are random per test run, so the accessibility gate failed only sometimes.

## Severity
- [x] P3 — minor content or admin issue

## Affected requirement / feature
- Requirement: NFR-001 (WCAG 2.2 AA; 1.4.10 Reflow)
- Story: MVP-012 (Product and release editor), unchanged since MVP-014

## Environment
- CI accessibility gate, Firefox at 320px, state `admin-products-edit-published`
- User role: admin

## Steps to reproduce
1. Run the accessibility gate (`pnpm test:a11y`).
2. The fixture's file scan ids are random. When one renders wide enough, `admin-products-edit-published @ 320px` reports "the page is 325px wide in a 320px viewport".

## Expected behavior
No horizontal scrolling at 320px, whatever the id.

## Actual behavior
325px wide in a 320px viewport (CI run 37526071015, shard 3, Firefox). The same state passed in the previous run of the same code.

## Evidence
- The failing page snapshot shows `cmux4qg7c000omo4c9byxxafx — CLEAN` in a nested list. Nothing else on the page is a long unbreakable word.

## Security or privacy impact
- [ ] None.

## Accessibility impact
- [x] Horizontal scrolling at 320px (WCAG 1.4.10), admin page only.

## Fix
- **Fix:** `ReleasesEditor.tsx` wraps the id in a span with `overflow-wrap: anywhere`, so it breaks when it has to. It's a span rather than a class on the list, so the list keeps its plain-element styles.
- **Found:** 2026-10-06, while CI ran on the MVP-036 PR, which fixes it.
