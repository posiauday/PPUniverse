Follows `planning/github/04-bug-template.md`. Found while measuring the accessibility baseline for MVP-023.

## Summary
The catalog search input (`SearchForm`) has a white background on a white page, so its only visible edge is a 1px light-grey border, and its only *visible* label is the placeholder (the real `<label>` is screen-reader-only). Both are below the required contrast.

## Severity
- [x] P3 — minor content or admin issue

## Affected requirement / feature
- NFR-001. WCAG 2.2 success criteria 1.4.11 Non-text Contrast (AA) for the control boundary and 1.4.3 Contrast (Minimum) (AA) for the placeholder text; 3.3.2 Labels or Instructions (advisory — the visible label disappears as the user types).
- Delivered by MVP-004 (`packages/ui/src/search-form.tsx`, token `--color-border` in `globals.css`).

## Environment
Local dev server, Chromium, 2026-09-21. Guest.

## Steps to reproduce
1. Open `/categories/power-apps-components` or `/search`.
2. Inspect the search field's border and placeholder colours.

## Expected behavior
Control boundary at least 3:1 against the adjacent background; placeholder text at least 4.5:1.

## Actual behavior
Border vs page **1.35:1**. Placeholder vs input background **3.46:1**.

## Evidence
Contrast computed from the browser's computed styles (border colour, placeholder colour blended over white). axe does not evaluate either.

## Security or privacy impact
- [ ] None.

## Accessibility impact
- [x] Blocks WCAG 2.2 AA conformance (1.4.11, 1.4.3). Apply `type:accessibility`.

## Suggested fix
Darken the input border token used for form controls to at least 3:1, use a placeholder colour of at least 4.5:1, and consider a visible label. Add a test asserting both ratios.

## Resolution
Fixed by MVP-023 F2 (commit 946c2d1, border) and F3 (commit 0d244f0, placeholder): two Tailwind classes on the search input. Re-measured on 2026-09-21 from computed style and from painted pixels in all three engines: border 7.48:1 (was 1.35:1) and placeholder 7.48:1 (was 3.45:1). Regression tests: `bug-004-input-border.spec.ts` and `bug-004-placeholder.spec.ts` in `packages/e2e/tests/a11y/regressions/`, each shown failing before its fix.
