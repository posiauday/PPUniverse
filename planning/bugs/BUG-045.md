Follows `planning/github/04-bug-template.md`. Found in the full-site code review the product owner asked for on 2026-10-10.

## Summary
POST /api/auth/signin/email (Auth.js) sent an email for every request, to any address, from any client. The password emails share per-address and per-IP budgets; the sign-in link bypassed them.

## Cause
The limits live in the password flow (PasswordAuth.mayEmail); the Auth.js email provider has none of its own and nothing wrapped it.

## Fix
The Auth.js route counts a sign-in link request against the same budgets (PasswordAuth.allowEmailTo: 5 an hour per address, 20 per IP). Over the budget no email is sent; the sign-in page says to check the last link or wait an hour.

## Steps to reproduce
Script requests for a sign-in link to one address in a loop.

## Expected behavior
After five emails in an hour, no more are sent.

## Actual behavior
Every request sent an email.

## Security or privacy impact
Inbox flooding, the Resend quota used up for everyone, and harm to the sending domain's reputation.

## Tests
nextauth-route.test.ts (counted, refused over budget as JSON and as a redirect, other Auth.js requests untouched); password-auth.test.ts (the shared budget).
