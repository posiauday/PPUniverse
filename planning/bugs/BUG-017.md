## Summary
`apps/web/lib/design-tokens.test.ts` finds the end of the "defaults for unstyled elements" CSS block by searching for a newline, a closing brace and a newline. With `core.autocrlf`, a Windows checkout has CRLF line endings, so the search failed, the scan ran on to the rest of the file, and the test failed on an unrelated `@keyframes` rule.

## Severity
- [x] P3. Test-only; CI (an LF checkout) was unaffected, and so was every page.

## Steps to reproduce
Check out the repository on Windows with `core.autocrlf=true`, then run `npx vitest run lib/design-tokens` in `apps/web`.

## Expected / actual
Expected: 38 passing tests. Actual: "only ever targets elements WITHOUT a class" failed with `@keyframes lcs-rise`.

## Why it was not caught earlier
The worktree used to build MVP-027 slice 4 had the file with LF endings (it was written there), so the test passed locally and in CI.

## Resolution (2026-09-30, MVP-028 slice 1)
The test normalises CRLF to LF when it reads `globals.css`. It now passes on both kinds of checkout: 448/448 web tests on a CRLF checkout.
