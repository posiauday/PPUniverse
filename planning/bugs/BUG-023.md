## Summary
The 2026-10-06 configuration review checked the live site's response headers. Netlify sends HSTS and `X-Content-Type-Options: nosniff`, but the site sent none of these:
- `Content-Security-Policy` (no `frame-ancestors`);
- `X-Frame-Options`;
- `Referrer-Policy`;
- `Permissions-Policy`.

Any other site could frame any page, including the admin Publish buttons. That is a clickjacking risk.

Separately, `docs/15-deployment.md` ("Make yourself the admin") told the product owner to open `/admin`, which had no page and returned "Page not found". That cost a confusing round trip.

## Severity
- [x] P2: a missing defence-in-depth control. There's no known exploit, and admin actions are POSTs that also need an admin session. But framing could trick a signed-in admin into a click.

## Steps to reproduce
1. Run `curl -sI https://lowcodestacks.com/`.
2. Only `strict-transport-security` and `x-content-type-options` are present among the security headers.

## Expected / actual
- **Expected:** every page refuses framing and limits the referrer.
- **Actual:** no such headers.

## Why it was not caught earlier
MVP-021 added headers only for `noindex`. No test asserted security headers, and the deployment checklist didn't list them.

## Resolution (2026-10-06, MVP-034)
- **Headers:** `apps/web/next.config.ts` sends on every response:
  - `Content-Security-Policy: frame-ancestors 'none'; base-uri 'self'; object-src 'none'`;
  - `X-Frame-Options: DENY`;
  - `Referrer-Policy: strict-origin-when-cross-origin`;
  - a restrictive `Permissions-Policy`.

  A unit test covers them. The CSP has no `script-src` yet: TD-029.
- **Admin home:** `/admin` is now an admin home page listing every admin area, and it returns the same 404 to non-admins.
