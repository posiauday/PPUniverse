## Summary
Two CI failures so far, on two different assertions, sharing the same shape: a click on
the sign-in page's "Send sign-in link" button appears to produce no effect at all — no
network request, no client-side validation state change.

| Run | Commit | State | What was checked | What happened |
|---|---|---|---|---|
| 4 | `e43e1aa` | `signin-sent @ 320px` | `role="status"` shows "check your email" | Stayed empty; no `/api/auth/*` request after the click (from Playwright's own action trace; this run predates the dedicated evidence capture) |
| 7 | `18b7b46` | `signin-send-failed @ 320px` | The email field's accessible description says "try again" | Stayed empty, `aria-invalid` stayed `"false"`; the failure-evidence network log shows only the initial page load — no `POST /api/auth/signin/email` at all, intercepted or otherwise |

**The correlations, stated plainly because they narrow the search:**
- Both **Firefox only** (chromium and webkit have never shown either).
- Both **at 320px only** (the same states at 375/768/1280px have never failed).
- Both on the **same control** (the "Send sign-in link" button, reached via
  `packages/e2e/src/pages.ts`'s `submitSignIn`, a plain `.click()`).
- Both show the **application's own handler never executing** — not a failed fetch, not
  a slow response, but no sign the click had any effect at all.

Both times, every other state, in every other engine, at every other width, in the
same run, passed. Neither run's server log showed any error.

## Decision (2026-09-21, direct product-owner instruction: "Run 7 failure / sign-in
submit signature")
- **Extended instrumentation authorized and applied** (test logic only, no product
  code, no suite configuration change): `packages/e2e/src/signin-click-diagnostics.ts`,
  wired into `submitSignIn` in `pages.ts` and read by `failure-evidence.ts`. On any
  future failure of a sign-in submit state, it captures: a hit test at the exact click
  point (`document.elementFromPoint`); whether the button was hydrated (a React fibre
  property present on the node) at that moment; its visibility, pointer-events,
  z-index, bounding rectangle and whether it was within the viewport; a capture-phase
  event log proving whether `click` and `submit` fired at all and on what target; and
  the Node-side timestamp gap between the route interception being registered and the
  click being issued.
- **Fixed classification criterion, decided in advance of any evidence:**
  - **PRODUCT DEFECT** if the click reached the button (hit test resolves to it, a
    click event fired on it) but no submit handler executed — a control interactive to
    the user but inert to the application.
  - **TEST DEFECT** if the click did not reach the button — hit test resolves elsewhere,
    the button was offscreen, overlapped, or zero-size at that instant, or the
    interception was not yet registered. Then the fix is the test's own
    actionability/readiness handling, stated as such.
  - **A third case** — click reached the button, a handler existed, but the request was
    still never issued — stops for a report rather than being forced into either
    bucket.
  - **Ambiguous evidence** also stops for a report rather than taking the cheaper
    reading.
- **Monitor, do not fix.** No fix is proposed or applied without fresh, evidence-backed
  classification and explicit approval. No retry, wait, timeout change, or conditional
  skip.
- **Does not block MVP-023.**
- **Merge position:** the instrumentation commit is the next sample (not a separate
  documentation-only push obtained purely to get a fresh CI run — the standing rule
  against re-pushing unchanged code until a check goes green applies here too). If that
  run is green, merge is permitted once the full completion rule holds. If it fails on
  this same signature, the new evidence is classified per the criterion above and
  reported before any fix. If it fails on something new again, that is treated as
  another new finding — instrumented, classified, reported — not fixed under this
  authorization.
- **This record stays open past merge**, monitor-only, with the instrumentation
  permanently in place.
