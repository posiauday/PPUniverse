Follows `planning/github/04-bug-template.md`. Found while implementing MVP-023.

## Summary
`handleSubmit` in `apps/web/app/signin/page.tsx` awaits `signIn()` with no try/catch. If the request itself throws (the network drops), the form stays in its sending state: the button reads "Sending link…" and ignores further presses. Before MVP-023 the same input was stuck because the button was `disabled`; MVP-023 F6 kept the "ignore a second submit while sending" rule with `aria-disabled`, so the behavior is unchanged, not new.

## Severity
- [x] P3 — minor content or admin issue

## Affected requirement / feature
- NFR-001 (an error the user cannot recover from without reloading; WCAG 3.3.1). Delivered by MVP-002.

## Steps to reproduce
Open `/signin`, go offline (or make `POST /api/auth/signin/email` fail at the network level), enter a valid email and submit.

## Expected behavior
An error message tied to the email field, focus on the field, and the form usable again.

## Actual behavior
"Sending link…" indefinitely; a reload is the only way out.

## Security or privacy impact
- [x] None.

## Accessibility impact
- [x] A dead end with no message. Apply `type:accessibility`.

## Suggested fix
Wrap the `signIn()` call in try/catch and route the failure through the existing `fail()` path; add a regression test that aborts the request.
