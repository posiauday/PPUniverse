## Summary
The product owner's first paste-test of lcsDataTable 0.1.0 (a draft, not published) failed with four errors: "PA2108: Unknown property 'Checked' for control type 'ModernCheckbox@1.0.0'", one for each selection checkbox. Studio also warned that `ModernCheckbox@1.0.0` and `ModernTabList@1.0.0` are older than the current 1.0.2.

## Cause
`Checked` is the property's name in Microsoft's documentation, not in Studio's YAML. Studio rejected it on `ModernCheckbox` at version 1.0.0 and again at 1.0.2 (the second paste-test, after a first fix that only changed the version). Microsoft's control page documents display names and gives no YAML example, so the README marked the name as "our best reading" until a paste-test.

## Fix
- The Data table's selection boxes are `Classic/CheckBox@2.1.0`. Their properties are long-standing: `Default` shows the selection; `Text` is the accessible name (transparent, so only the box shows); the box, border and tick use the accent colour; focus shows a 2 px accent border.
- The selection changes in `OnSelect` (a real click or key press), from the current selection. A classic checkbox also runs `OnCheck`/`OnUncheck` when its `Default` changes, so with those, unticking one row would have made Select all untick itself and clear every row.
- The gate's list of properties Studio rejects now has `Checked` on `ModernCheckbox`; run against the pasted YAML, it reports all four.
- `ModernTabList@1.0.0` only warns, and the Tabs component pasted with it, so it is unchanged.

## Expected behavior
The Data table pastes with no errors; ticking a row's box selects it, Select all selects every row, and unticking one row leaves the others selected.
