Follows `planning/github/04-bug-template.md`. Found while measuring the accessibility baseline for MVP-023.

## Summary
On `/account/sessions`, revoking a session removes it from the list with no status message and drops keyboard focus to `<body>`. The page is also unstyled (the Revoke button is glued to the date text and looks like plain text) and its title is the site name only.

## Severity
- [x] P3 — minor (authenticated self-service page)

## Affected requirement / feature
- NFR-001. WCAG 2.2 success criteria 4.1.3 Status Messages (AA), 2.4.3 Focus Order (A), 2.4.2 Page Titled (A).
- Delivered by MVP-002 (`apps/web/app/account/sessions/*`).

## Environment
Local dev server, Chromium, real local Postgres with a throwaway user and two sessions, 2026-09-21. Authenticated member.

## Steps to reproduce
1. Sign in (or use a session cookie for an existing session) and open `/account/sessions` with two sessions listed.
2. Activate "Revoke" on the other session.

## Expected behavior
A polite status message announces that the session was revoked, and focus moves to a sensible target (for example the list heading or the next Revoke button).

## Actual behavior
The session disappears (one item remains), `document.activeElement` is `BODY`, and no `role="status"` or `role="alert"` element exists. The failure branch does render a `role="alert"`, but success is silent.

## Evidence
State read from the DOM after a real click: 1 list item, `activeElement` = `BODY`, no live region. Screenshot of the unstyled page.

## Security or privacy impact
- [ ] None.

## Accessibility impact
- [x] Blocks WCAG 2.2 AA conformance (4.1.3, 2.4.3, 2.4.2). Apply `type:accessibility`.

## Suggested fix
Render a persistent live region that announces success, restore focus deliberately after `router.refresh()`, add a descriptive title through a route-level layout, and apply the design-system styles. Cover with the MVP-023 account spec.
