## Summary
After #124 was merged, the accessibility gate failed in Firefox at 320 px on three pull requests (#125, #126, #127), each time on a page from #124: `account-welcome-missing` (339 px wide), `account-profile` (345 px), `account-profile-avatar-picked` and `account-profile-admin` (343 px). #124's own run passed, and a local Firefox run passed 18 of 18, so it comes and goes.

## Cause
- **Welcome page:** its `<main>` and `<h1>` have no classes, so the site's base styles apply: a 44 px bold heading. "Welcome to LowCodeStacks" has one long word, "LowCodeStacks", about 320 px wide at that size, more than a 320 px phone has room for. Its exact width depends on which font is drawn when the check measures (the web font or the fallback while it loads), which is why it fails only sometimes. The sign-in confirmation and email confirmation pages use the same heading style with the same word.
- **Profile page:** the display name sits beside a 112 px avatar in a flex row, and nothing let it wrap inside a word. The gate's names end in a token like `zz-e2e-a11y-1f2e3d-w0-`, and Firefox won't break after a hyphen that comes before a digit, so part of the name couldn't wrap. A reader with a long name without spaces would see the same.

## Fix
- The base heading style (`main h1` without classes) is 36 px on phones and 44 px from 640 px up, and a word too long for the line now wraps rather than widening the page (`apps/web/app/globals.css`).
- The profile's display name can shrink and wrap anywhere (`min-w-0`, `overflow-wrap: anywhere`; `apps/web/app/account/profile/page.tsx`).

The first version of the fix used `overflow-wrap: break-word` on the heading. #128's CI then failed on `password-confirm` at 320 px (341 px wide): those pages already give `<main>` `overflow-wrap: anywhere`, and `break-word` overrode it. `break-word` wraps the text but doesn't let the heading's box shrink, so inside the sign-in card's flex row it held the card at its full width. The rule now uses `anywhere`.

Checked locally once space was freed, in Firefox at 320 px with Verdana forced on every element to stand in for CI's wider fallback font: the confirmation page was 340 px wide before the change to `anywhere` and 320 px after, and all 28 sign-in, sign-up, password and account states pass.

## Expected behavior
No page is wider than a 320 px screen, whatever the font and whatever a reader's name is (WCAG 1.4.10 Reflow).

## Accessibility impact
- [x] Fixed: WCAG 1.4.10 Reflow on the welcome, sign-in confirmation, email confirmation and profile pages at 320 px.
