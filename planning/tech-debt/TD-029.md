## What was deferred and why
MVP-034 added a Content-Security-Policy to every page (BUG-023), but only the parts that can't break the site: `frame-ancestors 'none'; base-uri 'self'; object-src 'none'`. A policy that also limits scripts and styles needs Next.js nonces. Next.js puts inline scripts on every page, so a strict `script-src` without nonces would stop the site working. Nonces mean generating them in a proxy (middleware) and render dynamically. That deserves its own change, with the accessibility gate run in all three browsers.

## Risk if left unresolved
If a cross-site scripting bug ever got in, a full CSP would have contained it. Today there is no such bug known: React escapes output, and guide Markdown is rendered with raw HTML disabled. The CSP is a second line of defence.

## Proposed resolution
- Add a nonce-based `script-src 'self' 'nonce-…' 'strict-dynamic'` and a matching `style-src` through Next.js's documented CSP set-up.
- Run it in report-only mode on a deploy preview first.
- Then enforce it, and extend the header test.

## Trigger to revisit
Before checkout or any feature that renders user-supplied HTML, or within the next two releases, whichever comes first.
