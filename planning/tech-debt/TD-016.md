## What was deferred and why
`ArticlePublishEvent` (`packages/db/prisma/schema/content.prisma`) records only that a
publish action happened — `articleId`, `actorUserId`, `action`, `createdAt`. It does not
snapshot the `Article`'s content (title/body/excerpt/type) at the moment of publishing.
FR-011's precedent ("Product releases are immutable after publication; corrections
create another version") implies a full version history where each correction is its
own retrievable snapshot, not just a timestamped fact that *a* publish happened.

Building real content versioning (a `ArticleVersion` table snapshotting the full
document on every publish, with a way to view/diff/restore prior versions) is
meaningfully more scope than this first pass needed to close FR-014 for tutorials,
patterns and comparison pages: there is currently no unpublish/republish/correction
path at all (`isValidArticleStatusTransition` only allows `DRAFT -> PUBLISHED`, a
one-way action), so there is nothing yet for a version history to distinguish between.
The event log still gives a real, append-only audit trail of *who* published *what
article* *when* — it just cannot answer "what did this article say before its last
correction," because there is no correction path yet either.

## Risk if left unresolved
- Once an edit-after-publish or republish path is added, there will be no way to see
  what a previously-published Article actually said at an earlier point in time —
  only that publishing happened.
- A future compliance or dispute question ("what did this tutorial claim on date X")
  cannot be answered from the data as it stands today.

## Proposed resolution
When a correction/republish workflow is added to `Article` (a natural next step once
editors need to fix a published piece), extend `ArticlePublishEvent` into a real
`ArticleVersion` table that snapshots the full document per publish/correction, and
backfill a single version row for every `Article` already `PUBLISHED` at that point
from its current column values. No data is lost by waiting — the current schema simply
has less than it will need.
