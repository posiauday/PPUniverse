## What was deferred and why
`Article.body` is authored and stored as Markdown source, but `apps/web/app/learn/[slug]/page.tsx`
renders it verbatim inside a `<div className="whitespace-pre-wrap">` — React text-node
escaping, no `dangerouslySetInnerHTML`, no Markdown-to-HTML conversion. A visitor sees
literal Markdown syntax (`# heading`, `**bold**`, `[text](url)`) rather than rendered
headings, emphasis or links.

This was a deliberate security-first choice, not an oversight: converting Markdown to
HTML and rendering it requires either a sanitizing renderer (a new dependency and its
own security surface — a sanitizer bug would reopen the exact stored-XSS risk this
story was careful to close) or a component-mapping renderer, and evaluating/adding
either was judged out of scope for closing FR-014's core requirement (editors can
publish content, it's indexable and reachable) in this first pass. Render-as-escaped-
text closes the security risk completely, at the cost of a materially worse reading
experience.

## Risk if left unresolved
- Published tutorials/patterns/comparison pages are functionally readable but visually
  poor — no headings, lists, code blocks, or links render as such.
- Editors authoring in Markdown will see their formatting silently ignored on the
  public page, which is likely to be reported as a bug by whoever authors the first
  real piece of content.

## Proposed resolution
Introduce a Markdown-to-HTML rendering path using an established, actively-maintained
sanitizing renderer (e.g. a `remark`/`rehype` pipeline with `rehype-sanitize` explicitly
configured to reject raw HTML passthrough, script/event-handler attributes, and unknown
tags), added as its own small story or folded into whichever story first needs richer
Article formatting. No schema change is needed — `Article.body` already holds Markdown
source; only the render path in `apps/web/app/learn/[slug]/page.tsx` changes.

## Resolved by (story/commit, once closed)
Pending — no story yet owns Markdown rendering for Article content.

## Resolution (2026-09-28, MVP-026)
`apps/web/app/learn/ArticleBody.tsx` renders the body with react-markdown 10.1.0 and remark-gfm 4.0.1 (MIT, pinned): headings, lists, links, tables and code become real elements. No raw HTML is rendered (no rehype-raw), so HTML typed into a body stays inert text. The default URL transform drops `javascript:` links, and there is still no raw-HTML sink (the no-raw-html guard passes). Unit tests cover structure, links, script/event-handler inertness, `javascript:` removal and the scroll regions; the accessibility gate renders a fixture article with a heading, list, link, code block and table at all four widths.
