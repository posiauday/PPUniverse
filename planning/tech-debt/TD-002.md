## What was deferred and why
`pnpm audit --audit-level=high` (validated real this time — TD-001 predicted exactly this) found two HIGH-severity advisories, both transitive dependencies of `prisma@7.10.0` itself (not our runtime code): `deepmerge-ts` (stack exhaustion, via `@prisma/config`) and `mysql2` (auth-plugin-downgrade credential leak, via `prisma`'s multi-provider CLI tooling — we only use PostgreSQL). `prisma@7.10.0` is the latest stable 7.x release; no patch exists yet that bumps these.

## Risk if left unresolved
Both are devDependency/build-time only — never shipped in the deployed app bundle — and `mysql2`'s vulnerability requires connecting to a malicious/downgraded MySQL server, which this project never does. Risk to the deployed application was already low. Still flagged and fixed rather than waved off, per the security-review gate.

## Proposed resolution
Pinned via `pnpm-workspace.yaml`'s `overrides`: `mysql2: ">=3.22.0"` (same major, 3.15.3→3.24.4, low regression risk) and `deepmerge-ts: ">=8.0.0"` (major bump, 7.1.5→8.0.2 — higher theoretical regression risk since it's a major version, but `@prisma/config` is the only consumer and its behavior was re-verified after the override).

## Resolved by (story/commit, once closed)
MVP-002. Verified: `pnpm audit --audit-level=high` reports zero vulnerabilities; `prisma generate` and `prisma migrate diff` re-run successfully after the override (see `planning/progress-report.md` MVP-002 section).
