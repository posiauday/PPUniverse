## What was deferred and why
The TRD's architecture default is a durable queue for scans, webhooks, email, indexing, and media processing (`CLAUDE.md` "Suggested implementation baseline" — that baseline names "a durable queue," not a specific vendor; the earlier text here attributing "BullMQ" to it was imprecise, since BullMQ only ever appeared as an unratified ADR-004 table row, corrected 2026-09-24). `apps/web/lib/complete-file-upload.ts`'s `completeFileUpload()` runs the entire MVP-006 pipeline (re-check upload policy against actual size, magic-byte verification, malware scan, zone move) synchronously inside the `POST /api/files/uploads/complete` request handler. No story yet owns setting up the actual job queue — `apps/worker` is still just a boot-proving scaffold from MVP-001, confirmed empty (no runtime dependencies at all) as of the 2026-09-24 pre-work analysis.

## Risk if left unresolved
A large file (up to the 50MB policy limit) held in memory (`getObject` reads the full object) and scanned inline blocks the HTTP request/response cycle for however long ClamAV's `INSTREAM` scan takes — this does not scale under concurrent uploads and risks request timeouts on slow scans. It also means a crash mid-scan leaves a `FileScan` row stuck in `SCANNING` with no retry mechanism.

## Proposed resolution
Move the pipeline into a real queue consumer once a story establishes the job-queue infrastructure. The `POST /api/files/uploads/complete` endpoint would then enqueue and return `202`/`QUARANTINED` immediately, with the client polling `GET /api/files/{id}` (already returns scan status) for the terminal result.

## Decision (2026-09-24, direct product-owner instruction — `docs/final-decisions.md`, "TD-004 architecture and sequencing")

Full pre-work: `planning/prework/TD-004-prework-analysis.md`.

- **Architecture decided:** a Postgres-backed job queue (`SELECT ... FOR UPDATE SKIP LOCKED`), not BullMQ+Redis or a managed platform. A new ADR is required before implementation.
- **A foundation story is proposed, not approved:** `PROP-007` in `planning/proposed-stories.md` — not on the backlog, not started.
- **Sequencing: BUG-015 must be resolved and merged first.** A job table is exactly the shared, cross-package CI state BUG-015 is about; landing this before BUG-015's isolation strategy is settled creates a second surface for the identical flake.
- This story's own migration onto the queue, once the foundation exists, is proposed as its own small follow-up (per PROP-007's scope), not bundled into the foundation story itself.
