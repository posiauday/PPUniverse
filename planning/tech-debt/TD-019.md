## What was deferred and why

MVP-012 added three new page routes: `/admin/products`, `/admin/products/new`,
and `/admin/products/[id]/edit`. `packages/e2e/src/page-routes.ts`'s
`GATED_ROUTES` list — the Vitest guard (`route-coverage.test.ts`, part of the
standard `pnpm test` run) that fails the build if a real `page.tsx` exists
with no corresponding gate entry — now lists all three, so `pnpm test`
passes.

**What did not land:** matching Playwright a11y states in
`packages/e2e/src/pages.ts` (`GATED_PAGES`) for any of the three routes — no
`admin-products-populated`/`admin-products-denied`/`admin-products-new`/
`admin-products-new-denied`/`admin-products-edit` states exist, unlike the
`admin-content-*` states `/admin/content`'s pages already have. The actual
axe/keyboard/overflow/title Playwright suite (`tests/a11y/pages.spec.ts`,
run via `pnpm test:a11y`) is driven entirely from `GATED_PAGES`, not from
`GATED_ROUTES` directly, so it does **not** currently exercise any of the
three new admin product editor pages, even though `GATED_ROUTES` lists them.

This was deferred rather than built because `pnpm test:a11y` needs a
production build (`pnpm build`), a one-time Playwright browser install
(`pnpm --filter @ppu/e2e browsers:install`), and a local or CI Postgres with
migrations applied and `E2E_ALLOW_DATABASE_WRITES=1` — none of which could be
reliably provisioned and verified end-to-end in this pass on top of the rest
of MVP-012's scope. Per `CLAUDE.md`'s Definition of Done guidance for exactly
this situation, this gap is recorded here rather than silently left unrecorded
or falsely claimed as passing.

## Risk if left unresolved

The admin product/release editor — a form-heavy surface with checkboxes,
selects, a data table, multiple independent sub-forms and a publish gate
that conditionally disables a button — has real WCAG 2.2 AA risk surface
(label association, error announcement, focus management, contrast) that no
automated check currently verifies. `/admin/content`'s equivalent pages are
covered; `/admin/products`'s are not, which is an inconsistency in the
gate's actual coverage versus what `GATED_ROUTES` implies.

## Proposed resolution

Add `admin-products-populated`/`admin-products-denied` (mirroring
`admin-content-populated`/`admin-content-denied`), `admin-products-new`/
`admin-products-new-denied`, and `admin-products-edit` states to
`packages/e2e/src/pages.ts`, seeded via `packages/e2e/src/seed.ts` (a
`draftProduct` fixture analogous to the existing `draftArticle`/
`publishedArticle` fixtures — likely also needing a seeded category,
license definition, support policy, compatibility entry and a CLEAN
`FileScan`/`ReleaseFile` if the edit page's fully-populated state is to be
exercised meaningfully, not just its empty-draft state). Then run
`pnpm build && pnpm --filter @ppu/e2e browsers:install && pnpm test:a11y`
against a local or CI Postgres with `E2E_ALLOW_DATABASE_WRITES=1` and fix
any WCAG 2.2 A/AA failures found, following the same "fix inside the story,
no allowlist" discipline `docs/final-decisions.md`'s MVP-023 decisions
established (Q37).
