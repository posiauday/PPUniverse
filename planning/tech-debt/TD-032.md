## What was deferred and why
MVP-042's speed check (`packages/e2e/tests/perf`, CI job "Page speed (report only)") measures Core Web Vitals on a throttled phone profile: 4x slower CPU, a 1.6 Mbps connection with 150 ms latency, 412 px wide, median of 3 cold loads. The approved budget (docs/final-decisions.md, 2026-10-06 and 2026-10-07) is LCP ≤ 2.5 s, CLS < 0.1, and, as the lab stand-in for INP, Total Blocking Time ≤ 200 ms.

Measured locally (Windows, 2026-10-07), after the two fixes below:

| Page | LCP | CLS | TBT |
| --- | --- | --- | --- |
| Home | 2,720 ms | **0.130** | **426 ms** |
| Guides index | 2,100 ms | 0.001 | **492 ms** |
| A guide | **2,640 ms** | 0.002 | **377 ms** |
| A technology hub | 2,116 ms | 0.002 | **443 ms** |

A blocking check would fail every PR, so it reports instead. That is the shortcut this record tracks.

## Already fixed while building the check
- The accent and code fonts are no longer preloaded, so they don't compete with what the first paint needs.
- The rise and word animations start at 25% opacity instead of 0. An element at opacity 0 doesn't count as painted, which delayed LCP. The guide page went from 3.8 s to 2.6 s, the hub from 3.0 s to 2.1 s.

## What's left
1. **Blocking time (all pages, about 380 to 490 ms):** one long task while the page hydrates, mostly the framework's own JavaScript (React DOM and the Next.js runtime, about 390 KB before compression). To investigate: fewer and smaller client components in the header (menu, search, theme toggle, updates badge), and loading the reading progress and feedback widgets later.
2. **Home page shift (CLS 0.13):** the headline re-wraps when the display font (Bricolage Grotesque) finishes loading about 3 s in on the slow profile. **Fixed 2026-10-07:** the product owner chose `font-display: optional` for that font (`docs/final-decisions.md`, "Display font and the Learn module design direction").
3. **Guide LCP (2.6 s):** just over budget on the slow profile.

## When to resolve
When the pages are within budget, remove `continue-on-error` from the "Measure page speed" step so the check blocks merges.
