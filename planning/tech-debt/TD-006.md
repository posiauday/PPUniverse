## What was deferred and why
MVP-005 delivers the compatibility model, its display, and the write-time rules. The rules live in `validateCompatibilityEntry` (`packages/domain/catalog/src/compatibility.ts`): a platform area is required with a release wave, the release year is in range (2019 through current year + 2), the wave is 1 or 2, **Tested requires an evidence summary and a last-verified date**, verified dates cannot be in the future, notes and summaries are capped at 500 characters, and invisible/bidirectional-override characters are stripped. The structural rules are also enforced by database CHECK constraints (migration `20260921000000_add_product_evidence`).

But the story has no creator or moderator write surface — the creator editor (MVP-012) and moderation queue (MVP-013) own that — so:
1. **Nothing calls `validateCompatibilityEntry` yet.** Today evidence rows can only be created by direct database access.
2. **There is no automated screening of notes and evidence summaries for private data.** The product owner's 2026-09-21 decision says evidence text must never expose private test-environment details, credentials, tenant identifiers, customer information or internal operational data. `normalizeDisplayText` removes spoofing characters and React escapes markup, but nothing detects a GUID-shaped tenant ID or a secret-looking string. That kind of screening is heuristic and belongs with the write path and the moderator's review.
3. **Who may assign statuses — decided 2026-09-21** (`docs/open-questions.md` item 6, part 2, now closed): creators assign Creator Declared; moderators assign Marketplace Reviewed; Tested is reserved. These role rules are not enforced anywhere yet because no write path exists, and the built vocabulary itself predates the decision (reconciled in TD-008).

## Risk if left unresolved
Once a write path exists, a creator could self-assign "Tested", or paste a tenant identifier into a public note, if that path skips the validator and reviewers aren't checking. Today the exposure is nil (no write path), which is why this is recorded rather than built now.

## Proposed resolution
- MVP-012 must call `validateCompatibilityEntry` on every save and surface its error codes to the creator.
- MVP-013's review checklist must include an evidence review step.
- Enforce the 2026-09-21 role rules at the write paths: creators may submit only Creator Declared; only moderators may set Marketplace Reviewed; nobody may set Tested (reserved). Depends on TD-008.
- Add a heuristic private-data check (GUID/tenant-ID and secret-shaped strings) as a warning to the reviewer, not as the sole control.

## Resolved by (story/commit, once closed)

**Partially resolved 2026-09-24 (MVP-012, branch `feature/mvp-012-product-release-editor`).**
Under the first-party-only publishing model (`docs/final-decisions.md`,
"First-party-only publishing model"), there is no creator distinct from
`ADMIN` and no moderator (MVP-013 superseded) — this record's "creator"/
"moderator" language describes actors that collapse to `ADMIN` and a not-
yet-approved future mechanism, respectively; the underlying gates this
record calls for are unchanged by that collapse.

**What landed:**
- `POST /api/admin/products/{id}/compatibility`
  (`apps/web/app/api/admin/products/[id]/compatibility/route.ts`) calls
  `validateCompatibilityEntry` on every write and surfaces its error codes
  as `fieldErrors`, closing point 1 ("nothing calls `validateCompatibilityEntry`
  yet").
- Point 3 (who may assign which status) is enforced end to end: the route
  additionally rejects any `evidenceStatus` other than `CREATOR_DECLARED`
  with a distinct `EVIDENCE_STATUS_NOT_PERMITTED_HERE` code, and
  `PrismaCatalogRepository.upsertCompatibilityEntry`
  (`packages/adapters/catalog/src/catalog-repository.ts`) refuses to
  persist anything else as defense in depth — even an ADMIN caller can
  never write `MARKETPLACE_REVIEWED` through this path. `TESTED` is
  rejected earlier, by the validator itself (`EVIDENCE_STATUS_RESERVED_OR_LEGACY`).
  Tested: `apps/web/app/api/admin/products/[id]/compatibility/route.test.ts`
  and `packages/adapters/catalog/src/catalog-repository.integration.test.ts`.

**What did not land, deliberately — TD-006 stays open for this:**
- **Point 2, the heuristic private-data screening, is NOT built by
  MVP-012.** No GUID/tenant-ID/secret-shaped-string detector exists;
  `normalizeDisplayText` (unchanged) still only strips spoofing/control
  characters and lets React's own escaping handle markup. MVP-012's scope,
  per its own governing prompt, is the write path and role enforcement
  only — the private-data heuristic was never in scope for this pass and
  has no other owning story yet. **TD-006 stays Open for this piece
  specifically**, not fully Resolved.
- MVP-013's review-checklist bullet is moot (MVP-013 is superseded with no
  approved successor); the evidence-review-step proposal it named has no
  current owner.
