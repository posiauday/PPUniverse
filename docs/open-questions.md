28. Reconciling MVP-005's built status vocabulary with the statuses decision (`planning/tech-debt/TD-008.md`). Needs product-owner confirmation of: (a) whether **Not Verified** remains a valid status (the decision lists only Creator Declared and Marketplace Reviewed); (b) that Marketplace Reviewed is a per-compatibility-entry *evidence status*, not `Product.status` — the decision says moderators "change the publication state"; (c) whether a reviewed date or reviewer is shown (Marketplace Reviewed is not verification, so the "Last Verified" column cannot carry it); and (d) sequencing. Safest reversible default: no change to the built vocabulary until confirmed; do the reconciliation as a small separate corrective change before MVP-012 lets anything be written, not folded into MVP-021.
29. MVP-021: should a category listing with **no PUBLISHED products** be indexable and in the sitemap? Categories have no publication state in the schema. Safest reversible default: derive it from data — `noindex, follow` and omitted from the sitemap until the category has at least one PUBLISHED product (no schema change; flips automatically).
30. MVP-021: canonical policy for category-page variants. MVP-004 canonicalized every variant (page, search, sort) to the base URL. Search-engine guidance is a self-referencing canonical for each page of a paginated series. Safest reversible default: `?page=N` (N>1) canonicalizes to itself; `?q=` (search within a category) is `noindex, follow` with the base canonical; sort/pageSize variants use the base canonical. This changes delivered MVP-004 behavior, so it needs confirmation.
31. MVP-021: Product structured data without `offers`, `review` or `aggregateRating` is valid schema.org but not eligible for search-engine Product rich results, and the Rich Results Test will report those fields as missing. Safest reversible default: implement as decided (real fields only, no offers) and document the limitation; alternative: defer Product JSON-LD until price exists (MVP-007).
